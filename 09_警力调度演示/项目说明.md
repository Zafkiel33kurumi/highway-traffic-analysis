# 交警警力调度指挥台 · 项目说明

这份文档把演示系统里**每一个功能**讲清楚：它解决什么问题、界面上在哪里、背后怎么算、演示时怎么用。
想看"怎么打开、怎么操作"，可以配合同目录的 `使用说明.txt` 一起看。

---

## 一、项目是做什么的

一句话：**用预测模型提前判断哪里会堵，再把有限的警力合理地铺到路网上去，并且支持人工干预。**

系统把一天切成 48 个时段（每段 30 分钟，从早上 6 点到次日 6 点），每个时段做四件事：

1. 算出 86 个断面的路况（车速、流量、占有率、拥堵概率）；
2. 根据路况自动派警，尽量让每个拥堵的地方都有人；
3. 用剩下的警力去"1 小时后可能堵"的位置提前待命；
4. 把这一刻的完整状态存一份快照，供事后回看。

> 名词解释
> - **断面**：公路上一个监测点，本演示共 86 个，编号 S001–S086。
> - **拥堵概率**：模型给出的"这个断面接下来会堵"的可能性，0–100%。
> - **警组**：一个出警单元（可以理解为一辆警车 + 若干警员），本演示可配置 4–40 组。

## 二、系统结构

```
浏览器（模板/index.html）
   │  每 2 秒请求一次 /tick
   ▼
Flask 服务（服务.py，端口 8766）
   ├── 预测：查 数据/网格.json（训练好的模型导出结果）
   ├── 调度：聚段 → 均衡覆盖 → 预置待命 → 手动改派
   ├── 设备诊断：三参数一致性检查
   └── 任务与历史：数据/任务记录.json
```

- 后端是**单文件 Flask**，没有数据库，任务和历史都存在一个 JSON 文件里。
- 前端是**单页 HTML + 原生 JavaScript + SVG**，没有前端框架，双击文件也能读懂。
- 任务只有被页面打开时才会推进；关掉页面不会在后台空跑。

### 文件清单

| 文件 | 作用 |
| --- | --- |
| `服务.py` | 后端：时钟、预测、派单、设备诊断、任务与历史接口 |
| `模板/index.html` | 前端：任务工作台 + 监测首页 + 地图 + 回看 |
| `数据/路段.json` | 86 个断面的静态属性：车道数、历史拥堵率、基线车速/流量/占有率 |
| `数据/网格.json` | 预测模型导出的 1728 种组合（时段 × 天气 × 日期类型 × 车道） |
| `数据/任务记录.json` | 任务列表、每个任务的状态和 48 个时段快照（运行时自动生成/更新） |
| `使用说明.txt` | 操作手册和演示时间线 |
| `项目说明.md` | 本文档：功能与原理说明 |

## 四、功能详解

### 4.1 任务工作台

**解决什么问题**：把"一天的执勤"当成一个可保存、可回看的任务，而不是一打开就从头跑。

- **新建任务**
  - 填任务名称（留空自动命名）；
  - 勾选管辖道路：干线一（S001–S064）、干线二（S065–S086），可只选一条；
  - 填可用警力 4–40 组；
  - 点"创建并开始"直接进入监测首页，时间从 06:00 开始。
- **任务列表**
  - 每行显示：名称和编号、辖区、警力、进度（已跑时段 / 48）、状态、当前时刻和拥堵数；
  - 支持"全部 / 运行中 / 历史"筛选，支持按名称或编号搜索；
  - 运行中的任务按钮是"进入监测"，已归档的是"回看"；
  - 删除任务会连同它的历史一起删除。
- **持久化**
  - 每次推进都把任务状态写回 `数据/任务记录.json`；
  - 服务重启后，没跑完的任务停在原时刻，打开后接着跑。

> 演示要点：工作台是"入口"，先讲这里有多个任务、可以随时新建，再点进一个任务看实时监测。

### 4.2 监测首页：六个关键指标

| 指标 | 含义 | 计算口径 |
| --- | --- | --- |
| 当前拥堵断面 | 辖区里概率 ≥30% 的断面数 | 副标题显示其中 ≥50% 的严重数 |
| 警力需求 | 按拥堵程度折算需要多少组 | 每个断面 ≥50% 记 2 组、30–50% 记 1 组，再求和 |
| 在岗警组 | 正在前往或现场处置的组数 | 副标题显示现场处置数和今日已完结数 |
| 待命警组 | 还没派单、可立即调动的组数 | 包含在预测点预置待命的组 |
| 平均到场 | 从派单到抵达现场的平均时间 | 单位分钟，按历史任务统计 |
| 设备异常 | 当前被判定为异常的断面数 | 四类故障合计 |

> 说明：指标只统计"当前辖区"内的断面；辖区外的路况仍画在图上（灰色），但不派警、不计入统计。

### 4.3 二维路网图

这是一张**示意路网**，不是真实地图：两条干线一上一下，断面按顺序均匀分布，位置不代表真实地理坐标。

图上元素：

- **路况**：蓝=畅通、黄=缓行、橙=拥堵、红=严重拥堵；线段颜色取相邻两个断面里更严重的一个。
- **断面圆点**：颜色与路况一致；严重的断面外面有一圈淡色光晕；放大后显示编号。
- **警员圆标**：带两位编号，颜色对应一/二/三/四中队；同一位置有多个警组时自动左右错开。
- **负责路段色带**：警员负责一整段路时，沿路画一条该中队颜色的半透明色带。
- **预置待命**：没派单但被安排到预测热点的警组，圆标会移动到那个断面，外面加虚线空心圈。
- **设备异常**：闪黄色光圈 + 头顶黄色感叹号。
- **非辖区**：道路和断面变暗置灰。
- **图例**：左上角默认只占一行，鼠标移上去才展开，避免挡地图。

**地图操作**

| 操作 | 效果 |
| --- | --- |
| 滚轮 | 以鼠标位置为中心缩放 |
| 按住拖动 | 平移地图 |
| 点断面圆点 | 放大到该断面，左下角弹出详情卡 |
| 点警员圆标 | 弹出警组卡，可发起手动改派 |
| ＋ / － / 复位 | 按钮缩放、恢复全图 |
| 全屏 | 隐藏侧栏、页头、指标、表格、事件流，地图铺满屏幕 |

**断面详情卡**：车速、流量、占有率、拥堵概率、需警力、在岗组数、设备健康度、负责警组。

> 交互细节：拖动和点击是分开判定的——移动超过 4 像素才算拖动，否则算点击；松手时按坐标找实际点中的元素，所以拖完不会误触，点警员也不会被拖动逻辑吞掉。

### 4.4 警力分配算法（本项目的核心）

#### 第一步：把连续拥堵的断面合成"拥堵段"

- 只看辖区内的断面，按干线分别处理；
- 概率 ≥30% 的连续断面合成一段；
- 中间最多允许隔 1 个不拥堵的断面（避免把一条拥堵带切得太碎）。

这样做的目的：**按"路段"而不是按"单点"思考**。一条 10 个断面的拥堵带，本质是一个问题，不是十个问题。

#### 第二步：轮次分配，先铺满再加强

对每个拥堵段计算"建议投入组数"：

- 基础 1 组；
- 峰值 ≥55% 且段内至少 3 个断面，加 1 组；
- 段长 ≥8 个断面，加 1 组；
- 每段最多 3 组。

然后按轮次派单：

1. **第一轮**：每个拥堵段至少 1 组，保证不同地方都有人；
2. **第二轮、第三轮**：只给"建议组数"更高的段补人。

所有段按"峰值概率 → 段长"排序，警力不够时优先保更严重的段。

#### 第三步：一名警员负责一段路（zone）

警力不足时，不是让一个警员只守一个断面，而是给他一整段连续断面：

- 在拥堵段内滑动一个窗口，窗口长度最多 **8 个断面**；
- 优先选"还没被覆盖的断面最多"的窗口，其次选"峰值概率最高"的窗口；
- 这段路内所有断面都算"已覆盖"，所以表格里的"缺口"会同步减少。

举例：一条 12 个断面的拥堵带只有 2 个警员，就分成两段各 6 个断面，而不是两个人都站在概率最高的那一个点上。

#### 第四步：剩下的人去预测热点待命

- 用预测模型看 **1 小时后**（2 个时段后）哪些断面概率 ≥30%；
- 排除已经被在岗警员覆盖的断面；
- 把空闲警组按距离就近分配过去，作为预置待命点；
- 如果某组原来的待命点仍然 ≥25% 且没被覆盖，就保留，不来回折腾；
- 警力严重富余时，也可以选择不出警、留在驻地。

待命组的状态仍然是"待命"，可以随时被派单；一旦派单，待命点自动清空。

#### 派单与到场

- 出发位置优先级：当前所在断面 → 待命点 → 驻地；
- 到场时间按距离折算：`1 + 距离 / 15`，限制在 1–6 个时段（30–180 分钟）；
- 到场后处置 3 个时段（90 分钟），然后返回，1 个时段后恢复待命；
- 自动派单的任务，如果抵达前路况已经缓解（概率 <14%），会自动撤单；
- **手动改派的任务不自动撤单**，避免"人刚派过去就被系统撤了"。

### 4.5 手动改派（人工干预）

**使用场景**：现场有临时情况（施工、事故、领导要求），需要把某个警员直接指到某个位置。

**操作步骤**：

1. 在地图上点一个警员圆标；
2. 弹出警组卡：当前状态、负责路段、预测待命点；
3. 点"改派位置"，地图进入改派模式（鼠标变十字）；
4. 点目标断面，系统立刻重排并返回新状态；
5. 按 Esc 或点"取消改派"可退出；回看模式下不提供改派。

**重排原则（尽量改动小）**：

- 只撤掉这个警组自己原来的在途/在场任务；
- 目标附近的连续缓行以上断面组成新的负责路段（最多 8 个）；
- 然后只给"没人管的拥堵段"补位；
- **已经在途/在场的其他任务一律不推翻**。

实测：改派一个警组后，其他组原有任务 0 个变化，只新增必要的补位任务。

### 4.6 预测热点条

地图下方有一条"预测热点"：

- 显示模型名称、预测时间（1 小时后）和前 6 个高风险断面及概率；
- 这些位置就是富余警组待命时参考的位置；
- 用的模型与整个项目的主预测模型一致，见下一节。

### 4.7 任务监控

- 每个任务一张卡：任务号、警组名称、负责路段（单点显示断面号，整段显示如 `S012–S019（8 个断面）`）、状态、进度条；
- 手动改派产生的任务带"手动"标记；
- 状态流转：`前往中 → 现场处置 → 已完成`，或 `已撤单`；
- 任务号格式 `RW + 日期 + 序号`，可追溯到警组和断面。

### 4.8 设备状态监测

**解决什么问题**：传感器坏了会给出错误路况，必须先发现、再决定要不要信这条数据。

系统把 86 个断面排成格子：

- 正常=深色，异常=红色，非辖区=变暗；
- 鼠标悬停显示断面号、健康度、故障类型；
- 下方"异常清单"列出断面、干线、故障类型、健康度、处置状态。

**四类故障与判定规则**

| 故障 | 现象 | 判定依据 | 健康度 |
| --- | --- | --- | --- |
| 数据冻结 | 数值连续多个时段不变 | 连续 4 个时段速度、流量都不变 | 45 |
| 速度掉零 | 速度变成 0 但还有流量 | 速度 <3 km/h 且流量 >50 辆/h | 40 |
| 数值尖峰 | 速度突然翻倍 | 速度超过该断面基线 1.7 倍 | 50 |
| 占有率漂移 | 占有率异常升高、速度正常 | 占有率偏离近几时段中位数 >22 个百分点，且速度偏离 <8 | 55 |

演示中按计划人为注入 5 个故障（S007 冻结、S033 掉零、S019 尖峰、S051 漂移、S068 冻结），用来演示"发现问题 → 图上定位 → 派警时人工复核"的流程。

### 4.9 历史回看

- 任务跑满 48 个时段后自动归档；
- 点"回看"后，页头出现一条时间条，可以拖动或点前后按钮；
- 每一格对应一个已保存的快照，包含：路况、警组位置、任务、设备、事件流、预测热点；
- 回看是**只读**的：不会改动历史，也不会让任务重新跑。

### 4.10 全屏演示

- 地图右上角"全屏"：隐藏侧栏、页头、关键指标、表格和事件流，只留地图、图例和居中时间；
- 再点"退出全屏"或按 Esc 返回；
- 全屏时任务照常推进，回看时间条也照常可用；
- 适合投屏讲解，不会因为页面元素太多而看不清路网。

## 五、预测模型是怎么来的

### 5.1 模型本身

来源：`07_成果展示/04_模型代码/整体规律模型.py`（随机森林）。

- **输入四个特征**：时段（0–23）、天气（6 级）、日期类型（工作日/周末/节假日）、车道数（2/3/4/5）；
- **输出**：拥堵概率，以及每车道流量、平均车速、占有率；
- **拥堵定义**：车速 <70 km/h；
- **为什么不用断面编号**：用了就变成"背下每条路"，学不到规律；不用断面编号，模型才能泛化到新数据；
- **概率校准**：分类器输出后用等温回归（isotonic）校准，让"说 30%"就真的接近 30% 的发生率。

### 5.2 演示里为什么查表而不是加载模型文件

训练好的 `.pkl` 有几十 MB，而演示只需要"给定条件 → 输出"的结果。项目已经把模型的全部输出导出成：

- `数据/网格.json`（本演示使用）；
- `07_成果展示/01_网页系统/prediction_data.js`（网页预测系统使用）。

两者逐项比对过 1728/1728 完全一致，所以演示直接查表，效果等价、启动更快。

键的格式是 `"小时|天气|日期类型|车道数"`，值的前四位是 `[每车道流量, 平均车速, 占有率, 拥堵概率]`。

### 5.3 从模型输出到断面路况

1. 按当前时刻、天气、车道数查网格，拿到该条件下的基准值；
2. 用"同条件下雨雪概率 / 晴天概率"算天气影响系数，限制在 0.5–2.5 倍；
3. 乘上该断面的历史拥堵率，得到这个断面的概率；
4. 叠加 ±6% 的确定性扰动（用"时段序号 + 断面编号"做随机种子，保证同一时刻刷新结果稳定）；
5. 车速、流量、占有率按断面历史均值比例缩放；
6. 最后叠加人为注入的设备故障。

> 这样既有"整体规律"（模型），又保留了"每个断面自己的特点"（历史比例），不会 86 个断面长得一模一样。

| GET | `/api/tasks/<id>/replay/<i>` | 取第 i 个时段的快照 |
| DELETE | `/api/tasks/<id>` | 删除任务及其历史 |
| POST | `/api/tasks/<id>/assign` | 手动改派，参数 `group / idx` |

所有写操作都用一把全局锁串行化，避免多个页面同时推进时互相踩状态。

## 八、边界与说明

- 本系统是**演示系统**，警力编制、派警规则、处置时长都是设定值，不是真实警力数据；
- 路网是示意图，断面位置不代表真实地理坐标；
- 设备故障是按计划人为注入的，用于演示诊断流程；
- 拥堵分级阈值（50% / 30% / 14%）按本模型输出分布标定，不套用行业标准；
- 预测模型用历史数据训练，遇到极端天气、临时管制等情况，实际表现可能偏离；
- 所有指标和派单只统计当前辖区内的断面。
